# Итоговый отчёт о тестировании PayFlow

**Проект:** PayFlow — учебный стенд мини-кошелька (финтех). **Объём:** полный цикл тестирования API, данных, интеграций, безопасности, UI, нагрузки и ИИ-бота. **Фокус проекта — тестирование;** приложение написано как стенд.
**Период:** 12 рабочих дней · **Репозиторий:** github.com/alena227/payflow-qa

## 1. Что тестировалось
Платёжный сервис: регистрация и вход (JWT, 2FA), счета в RUB и USD, переводы с комиссией, конвертацией и суточным лимитом, события в Kafka, уведомления, ИИ-бот поддержки. Внешние сервисы (курсы, антифрод) заменены моками WireMock.

## 2. Подход
- **Документация:** требования с ID и матрицей трассируемости, тест-план, 60 тест-кейсов в Qase.
- **Техники тест-дизайна:** классы эквивалентности, граничные значения, таблицы решений, попарное для валют.
- **Два режима стенда:** `BUGS=0` (эталон) и `BUGS=1` (сборка-кандидат с 15 внедрёнными дефектами) — тесты зелёные на первом, красные на втором, что подтверждает их диагностическую ценность.
- **Независимость тестов:** каждый тест создаёт своего пользователя, прогоны не зависят от порядка.
- **Тестовый оракул:** ожидаемые суммы считаются по требованиям (Decimal / BigDecimal), а не берутся из кода приложения.

## 3. Объём выполненных работ

| Вид тестирования | Инструменты | Что проверено |
|---|---|---|
| Функциональное API | pytest + requests | авторизация, 2FA, счета, переводы, комиссия, конвертация, лимиты, валидация |
| Целостность данных | pytest + PostgreSQL (SQL с CTE) | баланс = история операций, нет отрицательных балансов, деньги в NUMERIC |
| Интеграционное (Kafka) | pytest + confluent-kafka | ровно одно событие на перевод, JSON-схема, DLQ, идемпотентность |
| Интеграционное (моки) | pytest + WireMock admin API | отказ/таймаут антифрода, недоступность и кривые курсы |
| Безопасность | pytest + Burp Suite | JWT (истёкший, alg=none, подпись), IDOR, CORS, перебор пароля, обход 2FA |
| UI (e2e + мобильный) | Playwright (эмуляция iPhone/Pixel) | вход, 2FA, перевод, мобильная вёрстка |
| Java-автотесты | JUnit 5, Rest Assured, Cucumber, Allure | ключевые API-сценарии + 3 BDD-сценария на Gherkin |
| Нагрузочное | k6 | POST /transfers при 10/50/100 пользователях |
| Тестирование ИИ | pytest | prompt injection, утечка данных, галлюцинации, стабильность |

**Автотестов:** ~120 на Python (с учётом параметризации) + 31 на Java. **Ручной прогон:** 60 тест-кейсов в Qase + исследовательское тестирование + проверка в Burp.

## 4. Найденные дефекты

Всего **12 дефектов** (баг-репорты в [docs/bugs/](bugs/)):

| ID | Дефект | Severity | Как найден |
|---|---|---|---|
| BUG-001 | Комиссия округляется вниз вместо ROUND_HALF_UP | critical | граничные значения, вручную + авто |
| BUG-002 | Перевод ровно на суточный лимит отклоняется (`>=` вместо `>`) | major | граничное значение лимита |
| BUG-003 | В событии Kafka `amount_to` — число, а не строка; все уведомления уходят в DLQ | critical | контрактный тест Kafka |
| BUG-004 | Событие перевода публикуется в Kafka дважды | major | проверка «ровно один раз» |
| BUG-005 | USD→RUB: получателю зачисляется округление вверх, баланс ≠ история | critical | SQL-сверка с CTE |
| BUG-006 | CORS отражает любой Origin + credentials | critical | Burp Repeater |
| BUG-007 | IDOR: чужой счёт виден по id | critical | Burp Repeater |
| BUG-008 | Слабая проверка JWT (истёкший, без exp, alg=none) | critical | автотесты безопасности |
| BUG-009 | Мобильная вёрстка: горизонтальная прокрутка | major | Playwright (эмуляция) |
| BUG-010 | Мобильная вёрстка: таблица истории шире экрана | major | Playwright (эмуляция) |
| BUG-011 | ИИ-бот уязвим к prompt injection | major | LLM-тесты |
| BUG-012 | ИИ-бот галлюцинирует (выдумывает тариф) | major | LLM-тесты |

По severity: **6 critical, 6 major.** Критичные дефекты связаны с деньгами (округление, целостность) и безопасностью (JWT, IDOR, CORS).

## 5. Нагрузочное тестирование
`POST /transfers` держит норматив p95 < 500 мс и 0% ошибок до **50 одновременных пользователей** (p95 = 309 мс). При 100 пользователях время деградирует до p95 = 563 мс, но ошибок нет — система замедляется, а не отказывает. Подробности: [load-report.md](load-report.md).

## 6. Автоматизация и CI
- **GitHub Actions** ([.github/workflows/tests.yml](../.github/workflows/tests.yml)): при каждом пуше поднимается стенд в Docker, прогоняются Python- и Java-тесты, сохраняются Allure-результаты.
- **Jenkins** ([Jenkinsfile](../Jenkinsfile)): тот же pipeline для локального Jenkins (профиль `ci`).
- **Allure** — единый отчёт по Python- и Java-тестам.

## 7. Оценка качества и рекомендации
Сборка `BUGS=1` **не готова к релизу**: открыто 6 критичных дефектов (деньги и безопасность). Рекомендуется:
1. Исправить все critical-дефекты (BUG-001, 003, 005, 006, 007, 008) до релиза.
2. Повторить регрессию автотестами после исправлений.
3. Исправить мобильную вёрстку и усилить защиту ИИ-бота (major).
4. Провести нагрузочный тест на инфраструктуре, близкой к прод.

Эталонная сборка `BUGS=0` проходит все автотесты — целевое качество достижимо.
