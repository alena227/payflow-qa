## Вариант для hh (раздел «Проекты»)

**PayFlow — тестирование финансового сервиса с Kafka (учебный проект)**
github.com/alena227/payflow-qa

- Составила тест-план, требования с матрицей трассируемости и 60 тест-кейсов в Qase, нашла 12 дефектов (6 critical), оформила баг-репорты
- Написала ~120 автотестов на Python (pytest, requests, Playwright) и 31 на Java (JUnit 5, Rest Assured, Cucumber) с BDD-сценариями на Gherkin
- Проверила события в Kafka: доставку «ровно один раз», JSON-схему, дубли и DLQ
- Проверила целостность данных в PostgreSQL SQL-запросами с CTE (баланс = история операций)
- Протестировала безопасность API в Burp Suite и автотестами: JWT (истёкший, alg=none), IDOR, CORS, перебор пароля, обход 2FA
- Протестировала ИИ-бота поддержки: prompt injection, утечка данных, галлюцинации
- Провела нагрузочное тестирование переводов в k6 (до 100 пользователей), нашла точку деградации p95
- Настроила CI в GitHub Actions и Jenkins, отчёты в Allure

## Что уметь рассказать на собеседовании (по одному примеру на тему)
- **Баг с деньгами:** комиссия округлялась вниз; нашла закономерность на граничных значениях, один репорт на одну причину, посчитала влияние на бизнес.
- **SQL:** расхождение баланса с историей на копейку (BUG-005) видно только SQL-сверкой с CTE, через API не заметно — пример, зачем тестировщику SQL.
- **Kafka:** событие дублировалось / уходило в DLQ из-за неверного типа поля — контрактное тестирование по JSON-схеме.
- **Безопасность:** нашла IDOR и CORS в Burp; объясни, почему проверка владельца была при переводе, но не при чтении.
- **Автотесты vs ручное:** alg=none в Burp прошёл на чистой сборке, а автотесты на BUGS=1 нашли три дыры в JWT — зачем автоматизация.
- **Нагрузка:** p95 важнее среднего; нашла деградацию между 50 и 100 VU; 0% ошибок = система замедляется, но не падает.
- **Тестирование ИИ:** проверяем правила (не сменил роль, не раскрыл чужое, не выдумал факт), а не точный текст, потому что ответ модели каждый раз разный.
