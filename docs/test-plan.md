# Тест-план PayFlow

Версия 1.0 · Автор: Алена · Объект тестирования: PayFlow (учебный стенд мини-кошелька)

## 1. Цель
Проверить, что PayFlow корректно и безопасно выполняет денежные операции: регистрацию и вход (JWT, 2FA), переводы с комиссией, конвертацией и лимитом, публикацию событий в Kafka и их обработку, целостность данных в PostgreSQL, веб-интерфейс на десктопе и мобильных. Найти дефекты до «релиза» и оценить готовность.

## 2. Объем тестирования

**В объеме:**
| Область | Требования | Виды тестирования |
|---|---|---|
| Авторизация, JWT, 2FA, блокировка входа | REQ-AUTH, REQ-2FA | функциональное, негативное, security |
| Счета, пополнение | REQ-ACC | функциональное, IDOR |
| Переводы: комиссия, конвертация, лимит, валидация | REQ-TRF | функциональное, граничные значения, классы эквивалентности |
| Внешние сервисы (курсы, антифрод) | REQ-TRF-07 | интеграционное на моках WireMock |
| История, уведомления | REQ-HIST | функциональное |
| Kafka: события, схема, дубли, DLQ | REQ-EVT | интеграционное, контрактное |
| Целостность данных | REQ-DATA | SQL-проверки (CTE) |
| Безопасность API | REQ-SEC, REQ-AUTH-04 | security (JWT, IDOR, CORS, перебор, обход 2FA), Burp Suite |
| Веб-интерфейс | REQ-UI | ручное, Playwright, мобильная эмуляция (iPhone, Pixel) |
| Нагрузка | REQ-NFR-03 | k6: 10 / 50 / 100 виртуальных пользователей |
| ИИ-бот поддержки | — (требования в день 10) | prompt injection, утечка данных, галлюцинации |

**Вне объема:** реальные платежные шлюзы и курсы валют (заменены WireMock), нативные мобильные приложения, кроссбраузерность кроме Chromium/WebKit, отказоустойчивость кластера Kafka, локализация.

## 3. Подход
- **Техники тест-дизайна:** классы эквивалентности, граничные значения (комиссия 10/500 ₽, лимит 300 000 ₽, сумма 0.01 / 1 000 000, 2 знака после запятой), таблицы решений (2FA: код есть/нет/пустой/неверный), переходы состояний (счетчик неудачных входов → блокировка), попарное для валют (RUB→RUB, RUB→USD, USD→RUB, USD→USD).
- **Уровни:** API (основной — бизнес-логика), интеграционный (Kafka, БД, WireMock), UI e2e (ключевые сценарии + мобильная верстка).
- **Ручное тестирование:** по тест-кейсам в Qase + исследовательское тестирование сессиями по 30–45 минут (Swagger, UI, Burp).
- **Автоматизация:** pytest (API, DB, Kafka, security, UI на Playwright, LLM), Java (JUnit 5 + Rest Assured + Cucumber) — ключевые API-сценарии, k6 — нагрузка. Запуск в GitHub Actions и Jenkins, отчеты Allure.
- **Тестовые данные:** `.\infra\reset.ps1` перед каждым прогоном; пользователи alice/bob/carol/dave (см. README). Автотесты создают своих пользователей с уникальными email, чтобы не зависеть друг от друга.
- **Оракулы:** требования (`docs/requirements.md`), ручной расчет комиссии и конвертации в Decimal, JSON-схема события, SQL-инварианты.

## 5. Критерии
**Начала:** стенд поднят, `/health` = ok, тестовые данные загружены, тест-кейсы утверждены.

**Окончания:**
- выполнено 100% тест-кейсов приоритета high и ≥ 90% остальных;
- нет открытых дефектов severity blocker/critical;
- все автотесты зеленые на `BUGS=0`;
- подготовлен итоговый отчет (`docs/test-report.md`).

**Приостановки:** стенд не поднимается или `/health` ≠ ok; blocker-дефект, блокирующий > 30% кейсов.

## 6. Дефекты
- Учет: `docs/bugs/BUG-XXX.md` по шаблону `docs/bugs/_template.md` (+ при желании Qase Defects).
- **Severity:** blocker — работа невозможна или потеря денег у всех; critical — некорректные деньги, уязвимость с доступом к чужим данным; major — нарушение требования без обходного пути; minor — есть обходной путь / косметика с влиянием; trivial — косметика.
- **Priority:** high — исправить в текущей итерации; medium — в следующей; low — когда будет время.
- Жизненный цикл: New → Open → Fixed → Verified → Closed (или Rejected / Duplicate).

## 7. Риски
| Риск | Влияние | Митигация |
|---|---|---|
| Ошибки округления в деньгах | Потеря денег, жалобы | Граничные значения, расчет ожидаемого в Decimal, SQL-сверки |
| Утечка чужих данных (IDOR, JWT) | Критическая уязвимость | Отдельный security-набор, Burp |
| Дубли/потери событий Kafka | Двойные уведомления, рассинхрон | Тесты «ровно один раз», DLQ, идемпотентность |
| Нехватка памяти ноутбука | Нестабильные прогоны | Профили Compose, тяжелые прогоны в GitHub Actions |
| Недетерминизм LLM | Флаки-тесты | Проверка правил, а не текста; несколько прогонов |
