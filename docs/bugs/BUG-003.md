# BUG-003: В событии transfer.completed поле amount_to передается числом, а не строкой

| Поле | Значение |
|---|---|
| Severity | critical |
| Priority | high |
| Компонент | api (публикация событий в Kafka) |
| Окружение | PayFlow, сборка `BUGS=1`, commit `c0db431`, Redpanda Console v2.7 |
| Требование | REQ-EVT-02 |
| Тест-кейс | TC-045 |
| request_id | `7b4abc0d8629434b9af07da2fc6a11c3` |
| tx_id | `1ff1a573-1f7e-43cd-91e7-71efe7490691` |
| Статус | New |

## Предусловия
- Стенд поднят, профиль tools запущен (Redpanda Console: http://localhost:8081)
- Получен токен alice@example.com

## Шаги воспроизведения
1. `POST /transfers` `{"from_account_id": 4, "to_account_id": 5, "amount": "10.01"}`, запомнить `id`.
2. Redpanda Console → Topics → transactions → обновить страницу → фильтр по `id`.
3. Раскрыть сообщение → Value.

## Фактический результат
```json
"amount": "10.01",
"fee": "0.10",
"amount_to": 925.67,
```
`amount_to` — JSON-число, тогда как `amount` и `fee` — строки.

## Ожидаемый результат
`"amount_to": "925.67"`. В схеме `app/notifier/transaction_event.schema.json` `amount_to` ссылается на `$defs/money`: `{"type": "string", "pattern": "^[0-9]+\\.[0-9]{2}$"}`.

## Влияние
- **Пользователи не получают уведомлений ни об одном переводе.** notifier валидирует событие по схеме и отправляет его в `transactions.dlq`. Лог notifier:
  `"msg": "invalid message -> DLQ", "error": "schema violation at amount_to: 1000.0 is not of type 'string'"`.
  Воспроизводится на переводах RUB→RUB, USD→RUB и RUB→USD (автотесты `tests/events`).
- Любой другой потребитель, валидирующий схему, тоже отклонит событие.
- Потребитель, который читает число как float, может получить неточную сумму (например, 0.1 + 0.2 = 0.30000000000000004). Для денег это недопустимо.

> Уточнение: в первой версии репорта было ошибочно указано, что notifier обработал сообщение. Автотесты дня 6 и лог notifier показали, что событие уходит в DLQ, поэтому severity повышена до critical.

## Вложения
Value сообщения (Redpanda Console → Copy Value), partition 2, offset 29.

## Дополнительно
Воспроизводимость: всегда, на всех типах переводов.
