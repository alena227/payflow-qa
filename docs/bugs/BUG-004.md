# BUG-004: Событие перевода публикуется в Kafka дважды (одинаковый event_id)

| Поле | Значение |
|---|---|
| Severity | major |
| Priority | high |
| Компонент | api (публикация событий в Kafka) |
| Окружение | PayFlow, сборка `BUGS=1`, commit `c0db431`, Redpanda Console v2.7 |
| Требование | REQ-EVT-01 |
| Тест-кейс | TC-044 |
| request_id | `7b4abc0d8629434b9af07da2fc6a11c3` |
| tx_id | `1ff1a573-1f7e-43cd-91e7-71efe7490691` |
| Статус | New |

## Предусловия
- Стенд поднят, профиль tools запущен (Redpanda Console: http://localhost:8081)
- Получен токен alice@example.com

## Шаги воспроизведения
1. Один раз выполнить `POST /transfers` `{"from_account_id": 4, "to_account_id": 5, "amount": "10.01"}` → 201, запомнить `id`.
2. Redpanda Console → Topics → transactions → обновить страницу → фильтр по `id`.

## Фактический результат
Два сообщения с key `1ff1a573-1f7e-43cd-91e7-71efe7490691`, оба с `event_id = 68a5390f-aba1-4c59-ad48-29d0d510ac68` и одинаковым временем 25.11.2026 19:14:19 (local).

## Ожидаемый результат
Ровно одно событие `transfer.completed` на один перевод (REQ-EVT-01).

## Анализ
Одинаковый event_id говорит о том, что одно и то же событие отправлено повторно (похоже на ошибочный retry), а не о двух разных переводах. В БД перевод один.

## Влияние
- Потребители без идемпотентности обработают перевод дважды (двойные уведомления, двойной учет в аналитике и антифроде).
- notifier защищен: уникальный ключ `(event_id, user_id, kind)`, поэтому дублей уведомлений нет, но это только один из потребителей.

## Дополнительно
- Наблюдалось на переводе USD→RUB. Нужно проверить, повторяется ли на RUB→RUB, RUB→USD и других суммах (определить область).
- В топике есть и другие пары сообщений с одинаковым key за 24.11 (видно в Console), то есть поведение не единичное.
