# BUG-005: При переводе USD→RUB на счёт получателя зачисляется сумма, округлённая вверх, баланс расходится с историей на 0.01

| Поле | Значение |
|---|---|
| Severity | critical |
| Priority | high |
| Компонент | api / БД |
| Окружение | PayFlow, сборка `BUGS=1`, commit `6acab54`, Windows 11, Docker Desktop |
| Требование | REQ-DATA-01, REQ-TRF-04 |
| Тест | `tests/db/test_integrity.py::test_balances_match_transaction_history` (TC-049) |
| Статус | New |

## Предусловия
- Отправитель: USD-счёт с балансом не меньше 10.12 USD (10.01 + комиссия)
- Получатель: RUB-счёт **другого** пользователя
- Курс USD/RUB в сервисе курсов (WireMock): 92.4750

## Шаги воспроизведения
1. `POST /transfers` `{"from_account_id": <USD-счёт отправителя>, "to_account_id": <RUB-счёт получателя>, "amount": "10.01"}` → 201.
2. Запомнить `amount_to` из ответа.
3. Выполнить сверку баланса с историей:
   `Get-Content docs\checklists\sql\balance_check.sql | docker compose exec -T postgres psql -U payflow`
4. Сравнить, на сколько вырос баланс получателя, с `amount_to`.

## Фактический результат
- Ответ API: `"rate": "92.475000"`, `"amount_to": "925.67"`; в `transactions.amount_to` тоже 925.67.
- Баланс получателя вырос на **925.68**.
- Сверка (автотест, прогон на commit `6acab54`):

| Счёт | Валюта | balance | по истории | Разница |
|---|---|---|---|---|
| 701 | RUB | 62176.18 | 62176.17 | +0.01 |
| 703 | RUB | 37233.48 | 37233.47 | +0.01 |

Во входящих операциях обоих счетов есть переводы USD→RUB (`10.01` и `0.07` USD). USD-счета тех же пользователей (702, 704) сходятся с историей.

## Ожидаемый результат
По REQ-TRF-04 сумма конвертации округляется ROUND_HALF_UP до 0.01: 10.01 × 92.475 = 925.67475 → **925.67**. Именно эта сумма должна зачисляться на счёт, и по REQ-DATA-01 баланс должен совпадать с историей операций (разница 0).

## Анализ
| Перевод | amount × rate | HALF_UP (история) | Зачислено |
|---|---|---|---|
| 10.01 USD | 925.67475 | 925.67 | 925.68 |
| 0.07 USD | 6.47325 | 6.47 | 6.48 |

Вероятно, при зачислении получателю сумма округляется вверх (как ROUND_UP), а в историю пишется по ROUND_HALF_UP.

Баг проявляется, когда у `amount × rate` остаток после второго знака больше 0 и меньше 0.005: тогда HALF_UP округляет вниз, а зачисление — вверх. Если остаток ≥ 0.005 или его нет (10.00 USD = 924.75), оба способа дают одно и то же, и расхождения нет.

## Вложения
- Вывод `pytest tests\db -vv -k balances` (таблица расхождений выше)
- SQL-выборка входящих операций по счетам с расхождением (`to_account_id, currency, currency_to, amount, rate, amount_to`)

## Дополнительно
- Воспроизводимость: всегда при выполнении условия выше.
- Через API не обнаруживается: ответ и история показывают правильную сумму, расхождение видно только при сверке с балансом в БД.
- Обходного пути нет.
- Влияние: на переводах USD→RUB получатель получает лишнюю копейку из ниоткуда, баланс не сходится с историей операций, сверки с бухгалтерией и отчётность искажаются.
