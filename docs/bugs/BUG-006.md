# BUG-006: CORS отражает любой Origin и разрешает credentials

| Поле | Значение |
|---|---|
| Severity | critical |
| Priority | high |
| Компонент | api (настройки CORS) |
| Окружение | PayFlow, сборка `BUGS=1`, commit `6acab54`+, Windows 11, Burp Suite Community (Repeater) |
| Требование | REQ-SEC-02 |
| Тест-кейс | TC-054; чек-лист security.md → «CORS и заголовки» |
| request_id | `d961fa320f284aa6814c7a0731be0326` |
| Статус | New |

## Предусловия
- Получен токен alice@example.com
- Запрос `POST /transfers` перехвачен в Burp Proxy и отправлен в Repeater

## Шаги воспроизведения
1. В Repeater в запросе `POST /transfers` заменить заголовок на единственный `Origin: https://evil.example`.
2. Тело: `{"from_account_id": 3, "to_account_id": 5, "amount": "100"}` → Send.
3. Посмотреть CORS-заголовки ответа.

Быстрая проверка без Burp:
```powershell
curl.exe -i http://localhost:8000/health -H "Origin: https://evil.example"
```

## Фактический результат
```
HTTP/1.1 201 Created
access-control-allow-credentials: true
access-control-allow-origin: https://evil.example
```
Сервер отражает присланный Origin в `access-control-allow-origin` и одновременно разрешает credentials.

## Ожидаемый результат
По REQ-SEC-02 кросс-доменные запросы разрешены только с `http://localhost:8090`. Для Origin `https://evil.example` заголовок `access-control-allow-origin` не должен возвращаться.

## Влияние
- Браузер пользователя разрешит JavaScript на любом стороннем сайте читать ответы API PayFlow: балансы, историю, данные профиля.
- Сочетание «отражённый Origin + `allow-credentials: true`» — классическая ошибка конфигурации CORS. Если клиент хранит сессию в cookie, вредоносная страница сможет выполнять действия от имени пользователя.

## Дополнительно
Воспроизводимость: всегда. Для разрешённого Origin `http://localhost:8090` ответ корректный (`access-control-allow-origin: http://localhost:8090`).
