# BUG-007: IDOR — GET /accounts/{id} возвращает чужой счёт с балансом

| Поле | Значение |
|---|---|
| Severity | critical |
| Priority | high |
| Компонент | api (авторизация доступа к счетам) |
| Окружение | PayFlow, сборка `BUGS=1`, commit `6acab54`+, Windows 11, Burp Suite Community (Repeater) |
| Требование | REQ-ACC-02, REQ-SEC-01 |
| Тест-кейс | TC-051 |
| request_id | `fb7bbc3feb7447548bb28ad92a827899` |
| Статус | New |

## Предусловия
- `.\infra\reset.ps1`: счёт 5 принадлежит bob@example.com
- Получен токен alice@example.com (её счета — 3 и 4)

## Шаги воспроизведения
1. Под токеном alice отправить `GET /accounts/5`.

## Фактический результат
```
HTTP/1.1 200 OK
{"id": 5, "currency": "RUB", "balance": "55200.00"}
```
alice видит валюту и баланс счёта bob.

## Ожидаемый результат
`404 {"detail": "account not found"}`: по REQ-ACC-02 чужой и несуществующий счёт дают одинаковый ответ, чтобы нельзя было узнавать чужие данные и перебирать id.

## Влияние
- Утечка финансовых данных: перебрав id 1, 2, 3…, любой авторизованный пользователь узнает балансы всех клиентов, включая системный счёт комиссий.
- Нарушение банковской тайны; OWASP API Security Top 10: API1:2023 Broken Object Level Authorization.

## Дополнительно
- Воспроизводимость: всегда.
- Для сравнения: перевод с чужого счёта (`POST /transfers` с `from_account_id: 5`) корректно отклоняется 404, то есть проверка владельца есть при списании, но отсутствует при чтении.
- Перебор id подтверждён: `GET /accounts/99999` → `404 account not found` (x-request-id `a57a090e33144fb8a039609de897ba30`), а существующий чужой счёт → 200 с данными. По ответу видно, какие id существуют.
