# BUG-008: Слабая проверка JWT — принимаются истёкшие токены, токены без exp и с alg=none

| Поле | Значение |
|---|---|
| Severity | critical |
| Priority | high |
| Компонент | api (проверка JWT) |
| Окружение | PayFlow, сборка `BUGS=1`, commit `843abf7`, Windows 11 |
| Требование | REQ-AUTH-04 |
| Тесты | `tests/security/test_security.py::test_expired_token_rejected`, `::test_token_with_alg_none_rejected`, `::test_token_without_exp_rejected` (TC-052, TC-053) |
| Статус | New |

## Описание
Сервер проверяет подпись JWT, но не применяет остальные правила валидации. Это даёт три способа обойти авторизацию (все воспроизводятся на `GET /auth/me` и любом защищённом эндпоинте).

## Способ 1: истёкший токен принимается
- Шаги: собрать токен для существующего пользователя с `exp` в прошлом, подписать настоящим секретом `dev-secret-change-me`; отправить `GET /auth/me`.
- Факт: **200 OK**, пользователь авторизован.
- Ожидание: 401 — срок жизни токена 30 минут (REQ-AUTH-04).
- Риск: украденный токен остаётся действительным вечно; выход/ротация не ограничивают доступ по времени.

## Способ 2: токен с alg=none
- Шаги: собрать токен с заголовком `{"alg":"none"}` и без подписи; отправить `GET /auth/me`.
- Факт: **200 OK**.
- Ожидание: 401 — сервер должен принимать только HS256.
- Риск: злоумышленник подделывает токен с любым `sub` без знания секрета и входит под любым пользователем. (Проверено также вручную в Burp.)

## Способ 3: токен без поля exp
- Шаги: собрать токен `{"sub": "<id>"}` без `exp`; отправить `GET /auth/me`.
- Факт: **200 OK**.
- Ожидание: 401 — токен без срока действия не должен приниматься.
- Риск: бессрочный доступ.

## Корректное поведение (для сравнения)
Эти проверки работают правильно, значит, сломана именно часть валидации:
- токен с чужой подписью → 401 (`test_token_signed_with_other_secret_rejected`);
- токен с подменённым payload без переподписи → 401 (`test_tampered_payload_rejected`);
- токен несуществующего пользователя → 401.

## Рекомендация
При декодировании JWT требовать `algorithms=["HS256"]`, обязательные поля `exp` и `sub`, проверять срок действия.

## Дополнительно
Воспроизводимость: всегда. На сборке `BUGS=0` все три проверки проходят (401).
