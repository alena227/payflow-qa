## Проверено, уязвимость не обнаружена
| Проверка | Как | Результат |
|---|---|---|
| Отрицательная сумма перевода | Repeater, `"amount": "-100"` | 422 `greater_than` ✓ |
| Сумма с 3 знаками после запятой | Repeater, `"amount": "0.001"` | 422 `decimal_max_places` ✓ |
| Подменённый токен (изменён последний символ подписи) | Repeater | 401 `invalid token` ✓ |
| Перевод с чужого счёта (IDOR при списании) | Repeater, токен alice, `{"from_account_id": 5, "to_account_id": 3}` (5 — счёт bob) | 404 `source account not found`, деньги не списаны (x-request-id `854a6c8f375f4d248d7a405575d8fea1`) ✓. Первая попытка `5 → 5` проверила другое правило (422 «same account») |
| Запрос без токена | Repeater, `POST /transfers` без заголовка Authorization | 401 `not authenticated`, `www-authenticate: Bearer` (x-request-id `f5663f66be2248a78cf08c58c26d7a52`) ✓ |
| Изменение `sub` в payload токена без переподписи | Repeater → Inspector: `sub` 2 → 3, `GET /auth/me` | 401 `invalid token` (x-request-id `98095d08f5084a04a970c1862681c75d`) ✓: подпись проверяется |

## Вопросы к требованиям / рекомендации низкого риска
| # | Наблюдение | Почему важно | Рекомендация |
|---|---|---|---|
| Q1 | Сумма в экспоненциальной записи принимается: `"amount": "1e3"` → 201, переведено 1000.00 (x-request-id `b4af33bee2b3485cb64bdd2825feebb6`) | Формально соответствует REQ-TRF-02 (> 0, ≤ 1 000 000, ≤ 2 знаков), но формат не описан в требованиях: возможны неожиданные суммы от клиентов и сложности при сверке/логировании | Уточнить допустимый формат суммы; явно разрешить только `^\d+(\.\d{1,2})?$` |

## Перебор пароля (Burp Intruder) ⏳
- Цель: `POST /auth/login`, пользователь carol@example.com
- Словарь: 7 паролей (`123456`, `password`, `qwerty`, `carol`, `Passw0rd`, `letmein`, `Passw0rd!`)
- Результат: 7 запросов, часть 401 (неверный пароль), часть 429 (too many attempts). Верный пароль `Passw0rd!` (запрос 7) тоже получил **429**, а не 200: блокировка срабатывает даже когда перебор дошёл до правильного пароля.
- Примечание: первые запросы уже вернули 429, т.к. до Intruder под carol выполнялись ручные попытки входа; для чистого эксперимента стенд стоило сбросить. На вывод это не влияет.
- Вывод: эффективного перебора пароля нет — после 5 неудачных попыток вход блокируется на 5 минут (REQ-AUTH-06), и даже подобранный пароль не даёт войти. Уязвимость не обнаружена.

## Наблюдения по ходу работы
- Пустая строка в блоке заголовков HTTP завершает заголовки: всё после неё сервер читает как тело. При ручном редактировании в Repeater удалять заголовок нужно целиком, без пустой строки.
- Проверка «перевод на тот же счёт» выполняется раньше проверки владельца счёта, поэтому для проверки IDOR при переводе источник и получатель должны различаться.

## Рекомендации
1. CORS: разрешать только доверенные Origin из конфигурации (`http://localhost:8090`), не отражать Origin запроса, не включать `allow-credentials` без необходимости (BUG-006).
2. Проверять владельца объекта на каждом эндпоинте, который принимает id (`GET /accounts/{id}`); для чужого и несуществующего id отвечать одинаково 404 (BUG-007).
3. Зафиксировать формат денежных сумм во входных данных (Q1).
